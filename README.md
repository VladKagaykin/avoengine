## Введение

AVOEngine — это физический движок с акцентом на оптимизацию и кроссплатформенность. Он предоставляет:
- Двухмерную и трёхмерную отрисовку с попиксельным освещением.
- Динамические и статические очереди объектов и источников света.
- Систему карт для сохранения/загрузки сцен.
- Встроенный скриптовый язык Rhai для написания игровой логики.
- Многопоточный рендеринг для повышения производительности.
- Два способа вывода: графическое окно (через `softbuffer`) и цветная консоль (ANSI-коды).

Движок написан на Rust и использует минимальное количество внешних зависимостей: `winit` (окна и события), `softbuffer` (буферизация кадров), `image` (загрузка текстур), `rhai` (скрипты).

---

## Подключение к проекту

Поместите папку с движком (например, `avoengine_rust`) в корень вашего проекта и добавьте в `Cargo.toml`:

```toml
[dependencies]
avoengine = { path = "./avoengine_rust" }
winit = "0.30.13"
softbuffer = "0.4.8"
```

> **Примечание:** зависимости `image` и `rhai` уже включены в движок, указывать их отдельно не требуется.

## Глобальные настройки и состояние

Все глобальные данные хранятся в статических переменных с синхронизацией через `Mutex` или `LazyLock`.

### Settings

```rust
pub struct Settings {
    pub window_width: i128,   // ширина экрана в пикселях
    pub window_height: i128,  // высота экрана в пикселях
    pub tick_speed: i128,     // интервал между тиками в миллисекундах
    pub cores_multiply: u8    // множитель количества потоков рендеринга (по умолчанию 2)
}
```

### Engine_settings

Глобальный экземпляр настроек:

```rust
pub static Engine_settings: Mutex<Settings>
```

По умолчанию: `window_width = 58`, `window_height = 44`, `tick_speed = 50`, `cores_multiply = 2`.

### Camera_structure и Camera

```rust
pub struct Camera_structure {
    pub camera_fov: u8,          // поле зрения в градусах (для 3D)
    pub camera_x: f32,           // позиция камеры по X
    pub camera_y: f32,           // позиция камеры по Y (высота)
    pub camera_z: f32,           // позиция камеры по Z
    pub camera_pitch: f32,       // наклон камеры в градусах
    pub camera_yaw: f32,         // поворот камеры в градусах
    pub camera_roll: f32,        // крен камеры в градусах
    pub max_dist: u128,          // максимальная дальность видимости (для трассировки)
    pub ambient_light: [u8;3]    // цвет фонового освещения [R,G,B]
}
pub static Camera: Mutex<Camera_structure>
```

### Pixel_structure и Screen

```rust
pub struct Pixel_structure {
    pub pixel_symbol: char,         // символ для отображения
    pub pixel_RGBA_color: [u8;4]    // цвет [R,G,B,A]
}
pub static Empty_pixel: Mutex<Pixel_structure>   // пустой пиксель (прозрачный чёрный)
pub static Screen: Mutex<Vec<Vec<Pixel_structure>>>  // двумерный массив пикселей
```

### Draw_components и очереди

```rust
pub struct Draw_components {
    pub draw_type: String,          // "2d_object" или "3d_object"
    pub draw_x: f32,                // смещение по X
    pub draw_y: f32,                // смещение по Y
    pub draw_z: f32,                // смещение по Z (для 3D)
    pub draw_symbol: char,          // символ
    pub draw_vertices: Vec<f32>,    // вершины (2D: пары x,y; 3D: тройки x,y,z)
    pub draw_RGBA_color: [u8;4],    // цвет
    pub draw_texture_path: String,  // путь к текстуре или "none"
    pub draw_special_name: String   // произвольное имя
}
```

Очереди:
```rust
pub static Draw_queue: Mutex<Vec<Draw_components>>   // динамическая очередь (очищается после каждого кадра)
pub static Static_scene: Mutex<Vec<Draw_components>> // статическая сцена (сохраняется в карте)
pub static Is_scene_changed: Mutex<bool>             // флаг перестроения запечённого освещения
```

### Light_components и очереди

```rust
pub struct Light_components {
    pub light_x: f32,               // позиция X
    pub light_y: f32,               // позиция Y
    pub light_z: f32,               // позиция Z
    pub light_RGB_color: [u8;3],    // цвет
    pub light_distance: f32,        // дальность действия
    pub light_cone_angle: f32,      // угол конуса (градусы)
    pub light_pitch: f32,           // наклон (градусы)
    pub light_yaw: f32,             // поворот (градусы)
    pub light_special_name: String  // имя
}
```

Очереди:
```rust
pub static Light_queue: Mutex<Vec<Light_components>>   // динамическая (очищается)
pub static Static_light: Mutex<Vec<Light_components>>  // статическая (сохраняется)
```

### Script, Map_objects, Map_scripts

```rust
pub struct Script {
    pub function: String,   // имя функции (например, "on_tick")
    pub content: String     // код на Rhai
}
pub static Map_scripts: Mutex<Vec<Script>>
pub static Map_objects: LazyLock<Mutex<HashMap<String, String>>>   // хранилище ключ-значение
```

## Система тиков (tick_system)

Модуль `tick_system` обеспечивает равномерные обновления состояния игры.

**Публичные функции:**

- `Init_tick_system()` – инициализирует таймер, считывает `tick_speed` из настроек.
- `Tick_update()` – вызывается в главном цикле; увеличивает счётчик тиков, если прошло достаточно времени.
- `Get_tick() -> u128` – возвращает текущее значение счётчика тиков.

Счётчик тиков доступен из скриптов через `get_tick()`.

## Ввод с клавиатуры (console_input)

Модуль `console_input` предоставляет неблокирующее чтение нажатых клавиш (только для Unix‑подобных систем).

**Публичная функция:**

- `get_pressed_keys() -> Vec<char>` – возвращает вектор уникальных символов, нажатых в текущий момент. Очищает буфер ввода.

> **Важно:** этот модуль работает на низком уровне через `termios`. В Windows может потребоваться другая реализация.

## Окно и обработка событий (window_processing)

Модуль управляет созданием окна, обработкой событий клавиатуры и **выводом кадров в графическое окно** через `softbuffer`.

**Публичные функции:**

- `create_window(name: String) -> (Window, EventLoop<()>)` – создаёт окно с заданным заголовком, используя настройки ширины/высоты из `Engine_settings`.
- `update_frame(window: &Window) -> Result<(), Box<dyn std::error::Error>>` – **копирует содержимое глобального `Screen` в буфер окна** и выполняет `present()`.
- `update_key_state(key_code: KeyCode, pressed: bool)` – обновляет внутреннее состояние клавиш (вызывается из обработчика событий окна).
- `get_pressed_keys(_window: &Window) -> Vec<KeyCode>` – возвращает список всех нажатых в данный момент клавиш (коды `KeyCode`).

**Детали работы `update_frame`:**
1. Получает текущие размеры окна (`inner_size`).
2. Создаёт контекст и поверхность `softbuffer`.
3. Заполняет буфер чёрным цветом (фон).
4. Для каждого пикселя из `Screen` вычисляет блок оконных пикселей, соответствующий масштабу (ширина окна / ширина `Screen`, высота аналогично).
5. Каждый оконный пиксель в блоке окрашивается в цвет соответствующего пикселя `Screen` (преобразование RGBA в формат `softbuffer` — `u32` из байтов `[B, G, R, A]`).
6. Вызывает `buffer.present()` для отображения на экране.

**Использование:** В обработчике событий окна вызывайте `update_key_state` при событиях `KeyEvent`, а затем в основном цикле опрашивайте `get_pressed_keys`. После рендеринга вызывайте `update_frame`, чтобы показать результат.

## Рендеринг (console_rc_render)

Модуль выполняет всю работу по визуализации. Он состоит из двух основных подсистем: 2D-растеризация и 3D-трассировка лучей, а также предоставляет функцию для вывода в консоль.

### Основной рендер (заполнение Screen)

**Публичная функция:**
```rust
pub fn Render_image_to_console() -> Result<(), String>
```
- Собирает объекты из статической (`Static_scene`) и динамической (`Draw_queue`) очередей.
- Собирает источники света из статической (`Static_light`) и динамической (`Light_queue`) очередей.
- Выполняет 2D- и 3D-рендеринг, записывая результат в глобальный буфер `Screen`.
- Очищает динамические очереди после использования.
- Возвращает `Ok(())` при успехе или строку с ошибкой.

### 2D-рендеринг

- Объекты с `draw_type = "2d_object"` рисуются как залитые многоугольники.
- Вершины задаются в пикселях относительно верхнего левого угла экрана (ось Y направлена вниз).
- Поддерживается наложение текстур: если `draw_texture_path != "none"`, текстура натягивается на ограничивающий прямоугольник объекта.
- Альфа-канал учитывается при смешивании с фоном.

### 3D-рендеринг (трассировка лучей)

- Объекты с `draw_type = "3d_object"` разбиваются на треугольники (каждые 9 чисел в `draw_vertices` – один треугольник).
- Для каждого пикселя экрана испускается луч из камеры в направлении, определяемом FOV и размерами экрана.
- Выполняется пересечение луча с треугольниками сцены; выбирается ближайшее пересечение.
- Если у треугольника есть текстура, она накладывается с помощью барицентрических координат.
- Цвет пикселя вычисляется с учётом освещения и прозрачности (альфа-канал поддерживается).

### Освещение

- Используются источники света из статической и динамической очередей (фильтруются по конусу видимости).
- Для каждого пересечённого треугольника вычисляется нормаль и точка попадания.
- Тени рассчитываются методом трассировки лучей от точки к источнику света: если луч пересекает непрозрачный объект, тень засчитывается.
- Прозрачные объекты ослабляют свет в соответствии со своим альфа-каналом.
- Результат суммируется с фоновым освещением (`ambient_light` из камеры).

### Текстуры

- Поддерживаются форматы, читаемые библиотекой `image` (PNG, JPEG, BMP, GIF и др.).
- Текстуры кэшируются в глобальном `OnceLock<Mutex<HashMap<String, RgbaImage>>>`.
- Для 3D-объектов UV-координаты генерируются автоматически на основе ограничивающего прямоугольника треугольника (проекция на две наибольшие оси).

### Многопоточность

- Рендеринг 3D-сцены распараллеливается по строкам экрана.
- Количество потоков вычисляется как `(число_ядер * cores_multiply) - 1`.
- Каждый поток обрабатывает свой диапазон строк и записывает пиксели в общий буфер (синхронизация не требуется, так как строки не пересекаются).

### Вывод в консоль (To_console)

**Публичная функция:**
```rust
pub fn To_console()
```
- Берёт текущее содержимое `Screen` и печатает его в стандартный вывод (stdout) с использованием ANSI-кодов.
- Каждый пиксель отображается как один символ (`pixel_symbol`) с цветом `pixel_RGBA_color`.
- Цвет задаётся через последовательность `\x1b[38;2;R;G;Bm`, после каждой строки выполняется сброс форматирования.
- Эта функция предназначена для отладки или для работы в текстовом режиме (например, при запуске без графического интерфейса).

## Взаимосвязь Screen, окна и консоли

| Компонент | Назначение | Обновление |
|-----------|------------|------------|
| `Screen` (глобальный буфер) | Хранит пиксели в виде символов и цветов. | Заполняется в `Render_image_to_console()`. |
| Оконный вывод | Отображает `Screen` в графическом окне с масштабированием. | `window_processing::update_frame(&window)` |
| Консольный вывод | Печатает `Screen` в терминал цветными символами. | `console_rc_render::To_console()` |

**Типичный цикл приложения:**
1. `Render_image_to_console()` → заполняет `Screen`.
2. (Опционально) `To_console()` → печатает в консоль для отладки.
3. `update_frame(&window)` → показывает в окне.

## Карты (maps)

Модуль `maps` отвечает за сохранение и загрузку сцен в текстовом формате, а также за выполнение скриптов Rhai.

### Формат файла

Файл карты состоит из четырёх секций, разделённых комментариями:

```
// Map_objects
"key1" = "value1"
"key2" = "value2"

// Static_scene
Draw_components("2d_object", ...)
Draw_components("3d_object", ...)

// Static_light
Light_components(...)

// Map_scripts
Script("on_tick", "...")
```

**Детали синтаксиса:**
- Строки заключаются в двойные кавычки, внутри допускаются escape‑последовательности: `\n`, `\t`, `\\`, `\"`.
- Числа с плавающей точкой пишутся через точку.
- Массивы чисел заключаются в квадратные скобки: `[1.0, 2.0, 3.0]`.
- Цветовые массивы: для `Draw_components` – 4 элемента (RGBA), для `Light_components` – 3 элемента (RGB).
- Символы задаются в одинарных кавычках: `'#'`.
- Скрипты могут быть многострочными, парсер собирает всё содержимое до следующей секции.

### Функции Save_map / Load_map

```rust
pub fn Save_map(path: String) -> io::Result<()>
pub fn Load_map(path: String) -> io::Result<()>
```

- `Save_map` записывает текущие `Map_objects`, `Static_scene`, `Static_light` и `Map_scripts` в файл.
- `Load_map` очищает все статические данные и заполняет их из файла. После загрузки устанавливает `Is_scene_changed = true`, чтобы при следующем рендере пересчитать запечённое освещение.

## Скрипты Rhai

Скрипты выполняются при вызове `maps::Do_all_scripts()`, который обычно помещается в главный цикл после `Tick_update()`.

### Доступные функции

| Функция | Описание |
|---------|----------|
| `get_map_object(key: &str) -> String` | Возвращает строковое значение по ключу из `Map_objects`. Если ключа нет – пустая строка. |
| `set_map_object(key: &str, value: &str)` | Сохраняет пару ключ-значение. |
| `push_draw(comp: Draw_components)` | Добавляет объект в динамическую очередь (`Draw_queue`). |
| `push_light(light: Light_components)` | Добавляет источник света в `Light_queue`. |
| `get_tick() -> u128` | Возвращает текущий номер тика (можно использовать для анимации). |

**Регистрация конструкторов:** В скриптах доступны `Draw_components(...)` и `Light_components(...)` как функции, создающие соответствующие структуры. Параметры совпадают с полями структур (см. выше).
